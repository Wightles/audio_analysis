# Подключение ИИ-провайдера

Сейчас приложение работает в режиме `AI_PROVIDER=none`. Записи, история и ручное редактирование расшифровки доступны, но автоматическая транскрибация и анализ честно возвращают сообщение «ИИ-провайдер пока не подключён».

В проект добавлен необязательный адаптер Groq. Для его включения задайте значения только на backend:

```dotenv
AI_PROVIDER=groq
GROQ_API_KEY=<ключ>
GROQ_TRANSCRIPTION_MODEL=whisper-large-v3-turbo
GROQ_ANALYSIS_MODEL=llama-3.3-70b-versatile
GROQ_LANGUAGE=ru
GROQ_MAX_AUDIO_SIZE_MB=25
```

Если ключ отсутствует, приложение не выполняет внешних запросов и возвращает понятный статус недоступности. Для больших файлов адаптер сообщает о превышении лимита; автоматический chunking пока не включён.

Архитектура разделяет два этапа:

1. `TranscriptionService` получает аудио через `AIProvider.transcribeAudio()` и сохраняет расшифровку.
2. `MeetingAnalysisService` получает `TranscriptionResult` и `MeetingContext`, включая полный системный промпт Royal Brick, затем сохраняет полный `RoyalBrickReport`.

Контракт провайдера находится в `server/src/ai/provider.ts`, фабрика — в `server/src/ai/factory.ts`. Для нового сервиса нужно реализовать интерфейс `AIProvider` и зарегистрировать реализацию в фабрике. Ключи должны оставаться только в backend `.env`.

Перед сохранением анализа backend проверяет девять критериев, их веса, состояния `scored` / `no_data` / `not_applicable`, нормализованный балл и охват оценки. Несовместимый результат отклоняется и не попадает в SQLite.

После подключения провайдера проверяются маршруты:

```text
POST /api/meetings/:id/transcribe
POST /api/meetings/:id/analyze
GET  /api/meetings/:id/analysis
```

Перед будущей отправкой аудио внешнему сервису необходимо добавить отдельное подтверждение пользователя. Текущая форма согласия на запись не считается таким подтверждением автоматически.

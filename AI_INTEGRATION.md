# Подключение ИИ-провайдера

Приложение поддерживает режим без ИИ (`AI_PROVIDER=none`) и подключение Groq. В режиме без ИИ записи, история и ручное редактирование расшифровки доступны, а автоматические операции честно возвращают сообщение «ИИ-провайдер пока не подключён».

В проект добавлен необязательный адаптер Groq. Для его включения задайте значения только на backend:

```dotenv
AI_PROVIDER=groq
GROQ_API_KEY=<ключ>
GROQ_TRANSCRIPTION_MODEL=whisper-large-v3-turbo
GROQ_ANALYSIS_MODEL=openai/gpt-oss-120b
GROQ_PROMPT_MODE=compact
GROQ_LANGUAGE=ru
GROQ_MAX_AUDIO_SIZE_MB=25
GROQ_TPM_LIMIT=8000
```

`GROQ_PROMPT_MODE=compact` использует короткую рабочую версию промпта с теми же 13 разделами, правилами фактов и расчёта оценок. Оригинальный полный промпт хранится без изменений в `server/prompts/royal-brick-system-prompt.txt`. Для полного режима укажите `GROQ_PROMPT_MODE=full` и используйте тариф с достаточным TPM.

Если ключ отсутствует, приложение не выполняет внешних запросов и возвращает понятный статус недоступности. На странице встречи можно выбрать начало и конец аудиофрагмента: браузер временно формирует выбранный отрезок, отправляет его на расшифровку, а затем анализируется именно полученный текст. Автоматическое разбиение всей записи на части на сервере не включено.

Полный системный промпт Royal Brick не сокращается. Вместе с длинной расшифровкой он может превысить бесплатный лимит Groq по токенам в минуту и получить HTTP 413. В таком случае нужен Groq Developer Tier/другой лимит организации либо другой ИИ-провайдер; приложение не создаёт фиктивный отчёт и сохраняет встречу без анализа.

Архитектура разделяет два этапа:

1. `TranscriptionService` получает аудио через `AIProvider.transcribeAudio()` и сохраняет расшифровку.
2. `MeetingAnalysisService` получает `TranscriptionResult` и `MeetingContext`, включая полный системный промпт Royal Brick, затем сохраняет полный `RoyalBrickReport`.

Контракт провайдера находится в `server/src/ai/provider.ts`, фабрика — в `server/src/ai/factory.ts`. Для нового сервиса нужно реализовать интерфейс `AIProvider` и зарегистрировать реализацию в фабрике. Ключи должны оставаться только в backend `.env`.

Перед сохранением анализа backend проверяет девять критериев, их веса, состояния `scored` / `no_data` / `not_applicable`, нормализованный балл и охват оценки. Несовместимый результат отклоняется и не попадает в SQLite.

После подключения провайдера проверяются маршруты:

```text
POST /api/meetings/:id/transcribe
POST /api/meetings/:id/transcribe-fragment
POST /api/meetings/:id/analyze
GET  /api/meetings/:id/analysis
```

Перед будущей отправкой аудио внешнему сервису необходимо добавить отдельное подтверждение пользователя. Текущая форма согласия на запись не считается таким подтверждением автоматически.
